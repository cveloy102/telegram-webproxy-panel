# Сервер синхронизации СВАЛКИ

СВАЛКА — приложение дел и напоминаний для Android и Windows. Панель может поставить для него сервер синхронизации: тогда телефон и компьютер показывают одни и те же записи, а правки приходят за пару секунд. Это необязательная часть, без неё панель работает как раньше.

## Установка

Установщик задаёт вопрос после AmneziaWG:

```text
Установить сервер синхронизации СВАЛКИ (дела и напоминания: телефон ↔ компьютер)? да / нет
Домен сервера СВАЛКИ: [sync.example.com]
```

Нужен отдельный поддомен с A-записью на этот VPS. Сертификат выпускает тот же Caddy, что обслуживает панель. Уже установленную панель можно дополнить: запусти установщик ещё раз, выбери обновление и ответь «да».

Внутри это [PocketBase](https://pocketbase.io) (версия и SHA-256 закреплены в `svalka_install.py`) как служба `svalka-sync`. Он слушает только `127.0.0.1:8090`, наружу его отдаёт Caddy. Данные лежат в `/opt/svalka-sync/pb_data`.

Если на сервере уже стоит СВАЛКА из её собственного установщика (та же папка `/opt/svalka-sync`), панель берёт её под себя: аккаунты и записи сохраняются.

## Раздел в веб-панели

В меню «Управление» появляется пункт **СВАЛКА**:

- адрес, который вводят в приложениях;
- переключатель регистрации из приложений. По умолчанию закрыта, чтобы чужие не заводили аккаунты;
- создание аккаунтов, смена пароля, удаление.

Снаружи открыт только API для приложений. Админка PocketBase (`/_/`), вход суперпользователя и служебные API закрыты в Caddy (ответ 404). Если админка всё же нужна, открой её через SSH-туннель: `ssh -L 8090:127.0.0.1:8090 root@сервер`, затем http://127.0.0.1:8090/_/. Вход и регистрация ограничены по частоте с каждого адреса (10 попыток входа в минуту, 5 регистраций за 5 минут).

Панель ходит в PocketBase как собственный служебный администратор `panel@svalka.internal`. Его пароль лежит в `/var/lib/relay-panel/svalka.json` и доступен только панели.

## Резервная копия и перенос

База СВАЛКИ (`svalka/data.db`) входит в общую зашифрованную копию на Google Диске вместе с остальными данными панели. Восстановление требует, чтобы СВАЛКА на новом сервере была установлена с **тем же доменом**: приложения подключаются по домену, поэтому смена IP для них незаметна.

После восстановления сервер получает новую метку. Приложения замечают её и один раз сверяют все свои записи с сервером: то, что сделано на устройствах после момента копии, возвращается на сервер. Пока сервер недоступен, правки копятся на устройствах и уходят, когда связь появится.

## Обслуживание

```bash
systemctl status svalka-sync
journalctl -u svalka-sync -n 50
```

Панель администратора PocketBase: `https://sync.example.com/_/`.

Файлы `svalka/pb_hooks` и `svalka/pb_migrations` — копия папки `server/` из репозитория приложения. Обновляй их вместе.
