# Обслуживание

## Что установлено

| Путь | Содержимое |
|---|---|
| `/opt/relay-panel/releases/` | Исходники версий панели и установщика |
| `/opt/relay-panel/current` | Ссылка на активную версию |
| `/opt/MTProxy` | Исходники и собранный backend |
| `/usr/local/bin/tproxy-server` | Собранный релей |
| `/etc/relay-panel` | Состояние установщика, пользователи и ключи; только root |
| `/var/lib/relay-panel` | База владельца, 2FA, настройки и события; пользователь relayadmin |
| `/var/lib/tproxy-accounting` | IP и счётчики релея |
| `/srv/relay-site/index.html` | Публичная страница |
| `/etc/caddy/Caddyfile` | HTTPS и маршруты панели |
| `/var/backups/relay-panel` | Резервные копии с секретами; только root |
| `/var/log/relay-panel-install.log` | Журнал сборки и установки |

Службы: `caddy`, `mtproxy`, `tproxy-server`, `relay-helper`, `relay-panel`. Таймер `relay-refresh.timer` ежедневно обновляет маршруты Telegram; при изменениях перезапускает backend. Набор ключей при этом не меняется.

## Обновление

Повтори команду из README и выбери пункт 3. Сначала собирается кандидат и выполняются тесты. Затем панель и контроллер останавливаются, создаётся резервная копия и переключается версия. Пользователи, пароль, 2FA и статистика сохраняются; существующая страница не перезаписывается.

Откат при ошибке переключения автоматический, но его результат нужно проверять через `relay-panel status`. Обрыв питания или ручное завершение процесса в середине установки может потребовать восстановления из резервной копии.

## Резервные копии

Для автоматических зашифрованных копий в Google Диск и переноса на другой VPS используй [отдельную инструкцию](backups.md). Описанный ниже `relay-panel backup` сохраняет локальный **незашифрованный** архив для обслуживания и отката на том же сервере.

Для управляемой остановки старого сервера используй раздел **Перенос** или `relay-panel migration stop`. Проверка результата — `relay-panel migration status`, обратное включение — `relay-panel migration resume`. Панель остаётся доступной; остановленные Telegram/Hysteria не включатся при перезагрузке. Обновление установки в этом режиме блокируется до явного возобновления. Подробности, ошибки загрузки и восстановление с `--standby`: [Перенос и откат](backups.md#управляемая-остановка-старого-сервера).

```bash
relay-panel backup
```

Команда выведет путь к архиву. Архив доступен только root и содержит **рабочие ключи, данные входа и сертификаты**. Сохрани его вне VPS безопасным способом. SQLite копируется через API резервного копирования, а не простым копированием открытого файла.

Копия, созданная вручную, содержит данные и конфигурации. Копия перед обновлением дополнительно содержит программы. Автоматическая ротация старых копий пока не реализована: следи за свободным местом.

## Восстановление после неудачного обновления

Предназначено для **своей доверенной копии на том же VPS**. Не используй чужие архивы и не передавай резервные копии в публичные сервисы. Автоматически установщик вызывает восстановление сам.

Если оно не завершилось, администратор может повторить восстановление полной копии перед обновлением:

```bash
python3 -c 'import sys; sys.path.insert(0,"/opt/relay-panel/current"); from manage import restore_internal; restore_internal(sys.argv[1])' /var/backups/relay-panel/ИМЯ-ПОЛНОЙ-КОПИИ.tar.gz
relay-panel status
```

Это возвращает данные **на момент копии**, включая ключи и настройки. Перенос между серверами с другими uid/gid и доменами этим способом не поддерживается.

## Страница-заглушка

Название, контакт и тема задаются при первой установке. Для последующего изменения отредактируй `/srv/relay-site/index.html` и перезапусти `tproxy-server`. Панель управления содержимым сайта в эту версию не входит.

## Если потерял доступ владельца

- Потерял телефон — используй сохранённый резервный код вместо TOTP.
- Не успел создать владельца — `relay-panel setup-code` выдаст новый одноразовый код.
- Забыл пароль и потерял резервные данные — обычный установщик не сбросит защиту. Нужна своя резервная копия или отдельная процедура восстановления администратором.

## Удаление

Мастер удаления с очисткой секретов пока не включён. Для временного отключения пользуйся общей паузой в панели. Для окончательного удаления с отдельного VPS проще переустановить ОС у хостера **после сохранения нужных резервных копий**. Не применяй команды массового удаления к серверу с другими данными.
