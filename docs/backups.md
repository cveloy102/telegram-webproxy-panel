# Резервные копии и перенос

## Управляемая остановка старого сервера

Раздел **Перенос** останавливает службы Telegram WEB Proxy и опциональной Hysteria 2, сохраняет финальную зашифрованную копию на Google Диск и оставляет панель доступной. SSH, Caddy и отдельно установленная Amnezia не отключаются. Состояние переноса хранится только на этом VPS, вне переносимого архива; ключи и индивидуальные паузы клиентов не меняются.

1. Подготовь новый VPS и проверь, что файл приватного ключа восстановления сохранён вне старого сервера. Изменять DNS пока не требуется.
2. На старой панели открой **Перенос**, введи её домен и нажми **Остановить и создать финальную копию**. Подключения пользователей прервутся. Изменения данных будут закрыты; после остановки служб создаётся копия. У Hysteria сохраняется последний доступный опрос счётчиков: последние секунды активного трафика могут не попасть в учёт.
3. Дождись статуса **Сервер остановлен, финальная копия подтверждена**. Запиши имя архива. Проверяются размер и MD5 загруженного зашифрованного файла. Закрытие вкладки не отменяет операцию.
4. Скачай именно этот архив с Google Диска и продолжай восстановление ниже. Не удаляй старый VPS до проверки нового.

При ошибке загрузки старые службы остаются остановленными. Можно повторить остановку/загрузку либо возобновить прежнюю работу. Если отозван доступ к Диску, переподключи его в разделе **Копии**, затем повтори перенос. Во время активной операции настройки копирования менять нельзя. Служба копирования остаётся запущенной для управления, но автоматические копии приостановлены.

Остановка сохраняется после перезагрузки. Запуск служб защищён условиями systemd; прерванное возобновление не разрешает их запуск на следующей загрузке. Обновление панели во время остановки отклоняется. Не удаляй вручную `/var/lib/relay-migration`: это локальная защита от случайного включения старой установки.

Из SSH под root доступны те же операции, без браузера:

```sh
relay-panel migration status
relay-panel migration stop
relay-panel migration resume
```

`stop` и `resume` запрашивают домен для подтверждения и запускают фоновую операцию. Результат проверяй через `migration status`: принятие команды ещё не означает успешное завершение. Доступ по SSH/к панели старого VPS может потребовать другого VPN, если его IP недоступен из твоей сети.

Для отката сначала останови клиентские службы на новом VPS, верни DNS на старый и нажми **Возобновить работу** на старом. Вернутся только службы, работавшие перед остановкой; индивидуальные отключения ключей сохранятся. Панель не проверяет состояние второго VPS и не управляет DNS автоматически. Если после переноса на новом сервере менялись ключи или ограничения, данные старого VPS уже устарели: перед возвратом потребуется отдельно перенести актуальное состояние.

## Настройка автоматических копий

Во вкладке **Копии** укажи ссылку на папку личного Google Диска. Создай и скачай ключ восстановления. Сохрани его **отдельно от VPS и этой папки**, например в менеджере паролей. Сервер получает только публичный ключ `age1…`.

На своём компьютере установи [rclone](https://rclone.org/downloads/) и выполни:

```sh
rclone authorize drive
```

Выбери аккаунт Google и подтверди доступ. Вставь выданный JSON в «Подключить Google Диск». rclone запрашивает полный доступ к Диску; служба обращается только к выбранной папке. Это ограничение службы, а не OAuth-разрешений. Токен доступен только root на VPS, входит в зашифрованную копию. Отозвать его можно в настройках аккаунта Google.

Нажми **Создать копию** и дождись подтверждённой загрузки. После изменений ключей, входа, настроек и сайтов служба ждёт 10 секунд и создаёт новую копию. Проверка изменений — каждые 5 секунд, контрольный снимок трафика — раз в сутки. Данные SQLite копируются через Backup API. Неудачная загрузка не считается сохранением, повтор — через минуту. Данные разных служб снимаются последовательно, поэтому активный трафик может отличаться на несколько секунд.

Копия включает Telegram и Hysteria, их секреты и ограничения, историю IP и трафика, пароль/2FA владельца и страницы сайтов. Программы переустанавливаются из GitHub; HTTPS-сертификаты выпускаются заново. Архив шифруется стандартным age X25519 до записи и передачи на Диск. Проверяются размер и MD5 загруженного зашифрованного файла. Последние пять копий остаются на VPS. История на Диске не удаляется автоматически — следи за свободным местом.

## Если VPS потерян

### Мастер восстановления на новом VPS

На **новом чистом Ubuntu 24.04 amd64 VPS** запусти обычную команду установки из README и выбери **2 — восстановить из резервной копии**. Можно сразу открыть мастер:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/cveloy102/telegram-webproxy-panel/main/install.sh) --recover
```

1. Если старая панель доступна, открой **Перенос → Остановить и создать финальную копию** и дождись подтверждения Google Диска. Если старый VPS потерян, возьми последнюю успешную копию.
2. Скачай `.tar.gz.age` с Диска. Передай архив и сохранённый **`relay-recovery-key.txt`** на новый VPS в `/root/`. В WinSCP выбери SFTP, IP **нового** VPS, порт SSH (обычно 22), пользователя root и пароль или SSH-ключ. Справа открой `/root/` и перетащи оба файла с компьютера. Консоль установщика закрывать не нужно, архив распаковывать не нужно. Ключ — приватный ключ age, а не ключ SSH; не вставляй его содержимое в чат. Выставь файлу ключа права `chmod 600 /root/relay-recovery-key.txt` (если он сохранён без `.txt`, используй настоящее имя).
3. Мастер покажет найденные архивы и ключи в `/root/`: выбери файл по номеру либо укажи полный путь **на новом VPS**, например `/root/relay-backup.tar.gz.age`. Если найден один файл, Enter выбирает его; при нескольких выбор обязателен. Поддерживаются имена ключа `relay-recovery-key.txt` и `relay-recovery-key`; Windows может скрывать расширение `.txt`. Файлы в другой папке можно указать полным путём. Публичный IPv4 **нового** сервера определяется автоматически: если адрес в квадратных скобках совпадает с адресом в кабинете хостинга, просто нажми Enter. Иначе введи правильный IPv4 и нажми Enter. Мастер проверит расшифровку, целостность файлов и SQLite, покажет дату копии, прежние домены, порт Hysteria и число профилей. После подтверждения установит программы и восстановит данные. **Пока устанавливаются компоненты, DNS менять не требуется** — мастер отдельно покажет нужные записи. Новые временные клиентские ключи не обслуживают подключения: действует постоянный режим ожидания.
4. Мастер покажет конкретные A-записи и новый IP. В панели управления DNS замени старый IP у Telegram, Hysteria и сохранённых доменов-перенаправлений. Имена доменов оставь прежними. Убери AAAA-записи этих доменов; эта версия использует IPv4. В Cloudflare выбери **DNS only**. У хостера открой TCP 80/443 и указанный UDP-порт Hysteria.
5. Мастер повторяет проверки DNS и HTTPS, ожидая исправлений, и отмечает успешные шаги **✓**. HTTPS проверяется с обычной проверкой сертификата и имени домена. DNS проверяется через резолвер нового VPS; кэши провайдеров клиентов могут обновиться позже. Проверка с VPS не доказывает доступность UDP из каждой сети клиента.
6. Перед включением подтверди, что старый VPS выключен либо его Telegram/Hysteria остановлены. Недоступность старого сайта этого не доказывает. Затем мастер включает прежние службы и проверяет готовность Telegram, панели и Hysteria. Вход — с прежними паролем и 2FA; ключи клиентов сохраняются.

**Если SSH оборвался или нужно выйти:** нажми Ctrl+C и позже повтори ту же команду установки. Прогресс и копия зашифрованного архива хранятся в `/var/lib/relay-recovery/` (только root). Успешно импортированные данные повторно не заменяются; DNS и HTTPS всегда проверяются заново до завершения. Для ожидания можно отказаться от включения — службы останутся выключены, в том числе после перезагрузки.

Приватный ключ не записывается в файл прогресса. При продолжении **до окончания импорта** мастер снова попросит путь к нему; **после импорта** ключ больше не нужен. Переданный пользователем файл остаётся на VPS: после успешной проверки удали его с VPS самостоятельно, сохранив внешнюю копию. Очищенные при выходе расшифрованные временные файлы создаются в `/run`. Мастер не меняет DNS у регистратора и не выключает старый сервер автоматически. Прямое скачивание закрытого архива из Google Диска в этой версии не реализовано.

Мастер предназначен для нового VPS. На существующей чужой или обычной установке он откажется заменять данные. Для ручного восстановления на уже установленной панели используются команды ниже.

### Ручное восстановление

Обычные перенаправления дополнительных доменов на страницу Telegram также сохраняются: `redir https://ваш-домен{uri} 301/302/307/308` (или `permanent`/`temporary`). При переносе обнови DNS и этих доменов. Сторонние службы и произвольные правила Caddy вне проекта в переносимый архив не входят.

1. Скачай нужный `.tar.gz.age` из папки Диска. Возьми сохранённый `relay-recovery-key.txt`.
2. Купи новый VPS Ubuntu 24.04 amd64. Измени A-записи **всех прежних доменов** на новый IP, убери устаревшие AAAA-записи. Дождись обновления DNS.
3. Запусти обычную команду установки из README. Укажи **те же домены**, выбери те же Hysteria и AmneziaWG, которые были в копии. Открой TCP 80/443 и прежние UDP-порты VPN.
4. Передай архив и файл восстановления на новый VPS в `/root/` через SFTP/SCP. Выставь файлу ключа права `chmod 600 /root/relay-recovery-key.txt`.
5. Сначала проверь архив без изменения сервера:

```sh
relay-panel restore /root/your-backup.tar.gz.age --identity /root/relay-recovery-key.txt --inspect
```

6. Для восстановления повтори без `--inspect` и введи `ВОССТАНОВИТЬ`:

```sh
relay-panel restore /root/your-backup.tar.gz.age --identity /root/relay-recovery-key.txt
```

Чтобы восстановить данные, оставив клиентские службы и автоматические копии выключенными, добавь `--standby`:

```sh
relay-panel restore /root/your-backup.tar.gz.age --identity /root/relay-recovery-key.txt --standby
relay-panel migration status
# После проверки DNS, портов и сертификатов:
relay-panel migration resume
```

В режиме ожидания панель доступна, а ключи и настройки закрыты для изменений. Режим работает и с архивами, созданными до появления раздела **Перенос**. Обычное ручное восстановление без `--standby` по-прежнему включает службы автоматически. При ручной новой установке до восстановления службы сначала работают с временными данными; мастер восстановления выше сразу держит клиентские службы выключенными. HTTPS и сертификат Hysteria требуют корректного DNS и доступных портов. Это перенос с перерывом, а не автоматическое переключение без простоя.

Вернутся прежние пароль/2FA владельца и ключи клиентов. Службы кратковременно остановятся; перед заменой данных создаётся локальная копия. При ошибке выполняется откат. После проверки удали файл приватного ключа с VPS. Клиенты с доменами переподключатся после обновления DNS; клиентам с вручную указанным старым IP нужно исправить адрес.

Архив не заменяет отдельное хранение домена, доступа к Google и файла восстановления. Без приватного age-ключа содержимое восстановить невозможно. Изменение публичного ключа шифрования не меняет старые копии: для них нужен прежний ключ.

## AmneziaWG 3.1

При наличии AmneziaWG копия сохраняет её серверные ключи и маскировку, пользователей, клиентские ключи и PSK, внутренние адреса, лимиты, сроки и учёт трафика. Мастер восстановления устанавливает протокол из манифеста до импорта данных и включает службы только после выхода из режима ожидания. При прежнем домене и UDP-порте ранее выданные QR и `.conf` работают после смены IP и обновления DNS. [Подробности и проверка →](AMNEZIA.md)
