# Каскад RU → зарубежный выход

Основная панель, пользователи, ключи, Hysteria, AmneziaWG и Telegram WEB находятся
на российском VPS. Второй VPS обслуживает только WireGuard и выход в интернет.
Обычная установка без каскада продолжает работать.

Первая версия: один зарубежный IPv4-выход, весь клиентский трафик через него.
Разделения сайтов, приложений и пользователей по маршрутам пока нет. IPv6-трафик
клиентов блокируется. Доступность протоколов и UDP между VPS проверяется в своих сетях.

## Настройка

1. На RU установи основной проект или восстанови зашифрованную копию.
   A-записи входных доменов и панели должны указывать на RU. Домен для выхода не нужен.
2. Открой **Управление → Каскад**. Сохрани название, публичный IPv4 зарубежного VPS
   и UDP-порт, обычно 51821. Скопируй строку JSON с публичным ключом RU.
3. На отдельном чистом зарубежном Ubuntu 24.04 amd64 запусти обычный установщик
   и выбери **3 — выходной узел каскада**. Можно сразу передать `--exit-node`:

   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/cveloy102/telegram-webproxy-panel/main/install.sh) --exit-node
   ```

4. Вставь данные RU. Установщик создаст собственный приватный ключ на
   зарубежном сервере, настроит туннель/NAT/автозапуск и покажет публичный ответ.
   Открой входящий UDP-порт у хостера и в дополнительном firewall, если он есть.
5. Вставь ответ в панели RU. Нажми **Проверить выход**, затем **Включить каскад**.
   Проверка делает HTTPS-запрос через туннель, проверяет TLS и требует, чтобы
   наблюдаемый IP совпал с указанным IPv4 выхода. Хостинг с другим исходящим
   IP/NAT требует отдельной настройки. Одного handshake для проверки недостаточно.

Пароль root и SSH-ключ в панели не хранятся. Переносятся только публичные ключи.
Приватные ключи создаются и остаются на соответствующем VPS.
При переключении клиентские службы кратковременно останавливаются и запускаются
с новым режимом. Клиентам нужно переподключиться. SSH и панель остаются доступны.

## Поведение при отказе

Если `core.telegram.org` недоступен из RU ещё до установки панели, сначала запусти
тот же установщик на RU с `--prepare-cascade`. Он выдаст публичные данные для
зарубежного `--exit-node`, примет его ответ и проверит туннель. Затем повтори обычную
установку или `--recover`: публичные файлы Telegram загрузятся через подготовленный
канал. Приватные ключи повторно не создаются. Этот шаг не включает клиентский каскад.

При включённом каскаде нет автоматического перехода клиентов на прямой RU-выход.
Потеря связи с выходом или исчезновение интерфейса останавливает пользовательский
интернет. После восстановления WireGuard соединение возобновляется; старым сессиям
может понадобиться переподключение.
Контроллер раз в пять секунд проверяет собственный маршрут и правила выбора таблицы.
Если Linux удалил маршрут при выключении интерфейса, контроллер восстанавливает
интерфейс и маршрут с сохранением запрета прямого выхода.

Кнопка **Выключить каскад и разрешить выход через RU** возвращает обычный
режим. Это отдельное подтверждаемое действие. Менять адрес/ключ выхода можно только
при выключенном каскаде. Перед сменой ключей на установленном зарубежном узле
сохрани его `/etc/relay-cascade`: повторная установка не затирает ключи.

Клиентские systemd-службы зависят от `relay-cascade`. При аварии контроллера
они останавливаются. После устранения причины проверь каскад и явно запусти нужные
установленные службы; автоматическое снятие защиты не выполняется:

```bash
relay-panel status
journalctl -u relay-cascade -n 80
wg show wg-cascade
```

На выходе: `systemctl status relay-cascade-exit`, `journalctl -u relay-cascade-exit`.
Не публикуй `wg showconf`: он выводит приватный ключ.

## Резервные копии

На RU настройки и ключи туннеля входят в зашифрованные копии проекта и
локальные копии отката. Старые архивы без каскада поддерживаются; заранее настроенный
на новом RU выход сохраняется при восстановлении такого архива. Копия основного
сервера не содержит приватный ключ зарубежного VPS — безопасно сохрани его
`/etc/relay-cascade` отдельно. Не включай одновременно старую и восстановленную
RU-установки с одной туннельной идентичностью.
Раздел «Перенос» останавливает также межсерверный туннель и предотвращает его запуск
при перезагрузке. Это не даёт старому RU отправлять keepalive с ключом, восстановленным
на новом сервере. Возобновление сначала поднимает каскад, затем клиентские службы.

После восстановления архива с включённым каскадом недоступный выход не разрешает
прямой обход через RU. Перед запуском пользователей проверь оба сервера.

## Сеть

Проект владеет `wg-cascade`, подсетью `10.78.254.0/30`, таблицей маршрутизации
20781, приоритетами 10781/10782 и nftables-таблицами `relay_cascade` / `relay_cascade_exit`.
Конфликты проверяются перед первой установкой. Общие таблицы firewall и основной
маршрут VPS не очищаются и не заменяются.

AWG направляется по входному интерфейсу. Исходящие соединения Hysteria и MTProxy
направляются по UID служб; ответы на входящие подключения сохраняют обратный путь.
Внешние пакеты WireGuard имеют отдельную метку, исключающую повторное
попадание в туннель. NAT на RU и выходе обеспечивает обратный путь.
Hysteria использует собственный UDP DNS-resolver: клиентские DNS-запросы следуют
её выходному маршруту. Служебный DNS/обновления/копии RU работают через сеть RU.
Публичная конфигурация Telegram при подготовленном туннеле загружается через выход:
`core.telegram.org` может быть недоступен напрямую из российской сети даже при установке.

Сетевой smoke-тест: `sudo python3 tests/smoke_cascade.py`. Он создаёт временные
изолированные пространства сети и проверяет оба пути клиентского трафика,
ответы входного сервера, обрыв, сохранение управления, восстановление и выключение.
